# 联机：真实会话、协作副本与竞技

v10 的联机客户端为 [`src/online.js`](../src/online.js)，服务器为 [`cloudflare-worker/worker.js`](../cloudflare-worker/worker.js)。客户端和服务器使用同一套版本为 `10` 的 WebSocket 协议。**本次没有部署公共服务器或完成跨设备公网实测**；本地协议与客户端集成测试的实际范围见 [验证记录](verification.md)。

## 玩家使用

在游戏中打开联机面板，填写显示名和队伍标记。显示名独立于离线英雄姓名，队伍标记只是展示文本，不是账户或公会认证。

| 服务地址 | 实际连接范围 | 可用功能 |
| --- | --- | --- |
| 留空 | 同一浏览器、同一来源的其他标签页，通过 BroadcastChannel 通信 | 真实标签页在线名单、同地点聊天 |
| 已部署的 `wss://…` v10 端点 | 同一服务器领域中的实际 WebSocket 连接 | 在线名单、同地点聊天、2–4 人副本、1v1、3v3 |

同源要求协议、域名和端口一致，例如 `localhost` 与 `127.0.0.1` 不是同一个来源。标签页模式不会连接其他电脑，没有自动生成的队友，也不提供协作/竞技奖励。它不使用 WebRTC，不代表全服在线。

填写 WebSocket 地址后，客户端收到 `welcome`、发送经过规则约束的角色快照，并收到匹配会话的 `ready` 才显示连接成功；仅打开 socket 不算就绪。HTTPS 页面使用 `wss://`。没有服务、版本不符或握手超时会明确显示错误。

### 协作副本

1. 至少两名玩家连接同一领域，并在游戏中移动到同一地点。
2. 各自点击协作副本，进入同一个最多四人的队伍。首位加入者是队长。
3. 队长在人数达到要求后开始。加入、等待和开始都不发奖。
4. 每回合查看首领意图，选择攻击、职业技能、防御或自我治疗。职业技能有冷却，每人每场有两次治疗。
5. 全部存活参与者提交行动，或达到 20 秒时限后，服务器结算该回合。超时者自动防御。

首领有集中攻击、横扫、恢复三种意图；生命低于阈值时进入狂暴阶段。生命、伤害、冷却、治疗次数和贡献由服务器保存。战斗采用单独的入场生命和属性快照，期间不能通过同步离线装备来修改入场属性。

胜利奖励只发给仍连接且至少主动提交过一次有效行动的参与者；全程超时自动防御不算贡献。已经倒下但此前作出贡献、仍在会话中的队员可以共享胜利。失败、平局、进入副本和离开副本不产生奖励。客户端收到合法的结束快照和对应结算后才写入离线英雄，并记录奖励 ID 防止重复领取。

### 竞技场

1v1 需要两个不同的实时会话；3v3 必须等待六个不同的实时会话，不会用机器人补齐。两种匹配队列分开，重复点击不会增加自己的队列人数。队伍由服务器分配。

竞技场使用按职业固定的入场属性，减少离线存档数值差距；仍保留三职业各自的技能、防御和治疗决策。双方回合攻击统一结算；不能攻击队友，不能重复提交同一回合或重放旧回合。30 回合后仍未分出胜负则判平。排队期间没有奖励，未作出贡献的对手弃权胜利也不发奖。

排队、队伍大厅和正在进行的战斗会锁定相关离线行动，避免同一角色同时进行单人战斗、换装或改变入场快照。退出队列可以恢复普通游玩；战斗中退出或断线按离场处理，不能恢复该场会话。

## 部署自己的领域

部署需要 Cloudflare 账户及可用的 Workers / Durable Objects 环境。仓库中的 [`wrangler.toml`](../cloudflare-worker/wrangler.toml) 保留了 `AETHELGARD_REALM` 绑定和 `AethelgardRealmDO` 类。按照 [Cloudflare Durable Objects 文档](https://developers.cloudflare.com/durable-objects/) 准备 Wrangler 后，在服务器目录执行：

```bash
cd cloudflare-worker
npx wrangler login
npx wrangler deploy
```

这是供部署者执行的说明，不表示本仓库已经执行过部署。部署完成后，将实际地址的 `https://` 改为 `wss://`，填入游戏联机面板。例如：

```text
wss://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev/websocket?realm=friends
```

`realm` 由 1–48 个字母、数字、下划线或连字符组成，省略时使用 `global-shard-1`。同一 `realm` 进入同一个 Durable Object；不同领域的在线名单、队列和战斗隔离。服务器接受 `/`、`/websocket`、`/health` 的 GET 请求，普通 HTTP 返回当前协议和会话统计。

如需限制允许发起连接的网页来源，可在 Wrangler 配置中增加：

```toml
[vars]
ALLOWED_ORIGINS = "https://YOUR-SITE.example,http://127.0.0.1:8765"
```

该值按完整 Origin 精确匹配，逗号分隔；未配置时不做来源白名单限制。来源检查不等于玩家身份认证，非浏览器客户端能够自行设置请求头。

部署后应在两台独立设备上验证握手、同地点聊天、完整副本、决斗、断线与重复结算处理；3v3 需要六个实际会话。当地连接成功或单元测试通过，不能代替这一轮公网验证。

## 协议概要

所有数据包是 JSON 文本。服务器创建 session ID，并将它绑定到 WebSocket；不会采用客户端传入的发送者 ID 执行别人的行动。

| 阶段 | 客户端请求 | 服务器消息 |
| --- | --- | --- |
| 握手 | `hello`，含 `protocol: 10` 与 `passport` | `welcome` → `ready`，双方确认同一会话 |
| 在线与位置 | `ping`、`sync` | `pong`、`synced`、`presence` |
| 同地点聊天 | `chat`，仅发送文本 | `chat`，服务器附上发送者与实际房间 |
| 协作 | `raid_join`、队长 `raid_start` | `battle`，含队伍/首领/回合快照 |
| 竞技 | `arena_queue`，`mode: duel` 或 `team`；`queue_leave` | `queue`、`queue_left`、匹配后的 `battle` |
| 回合 | `battle_action`，含战斗 ID、回合号、行动与目标 | 更新后的 `battle` |
| 离场与结算 | `battle_leave` | `battle_left`；结束时 `battle_result` |
| 错误 | 无效或不合时序的请求 | 带错误代码和中英文说明的 `error` |

`battle_result` 包含 `battleId`、`sessionId`、`rewardId`、`outcome`、`eligible` 和有界奖励。客户端要求该战斗已经结束、结果属于当前会话、ID 未领过、奖励类型和数值有效。不能仅凭一条“胜利”聊天文本或一次启动事件发奖。

## 服务边界与限制

- 每个领域最多 100 个连接。角色快照接受三个已知职业，对等级、攻击、法术、防御与生命作有限值校验和上限约束；排队或战斗中拒绝修改快照。
- 单条 WebSocket 文本最多 8,192 个字符，拒绝二进制包；每会话最多 45 条消息/10 秒。聊天最多 240 字符，两次发送至少间隔 800 毫秒。
- 未完成握手的连接约 15 秒清理，静默会话约 90 秒清理，队伍大厅约 120 秒过期，竞技队列约 180 秒过期；周期检查可能带来数秒差异。
- 当前使用原生 WebSocket `accept()` 和内存中的战斗状态，没有实现休眠恢复、持久化战斗、跨重启重连或账户排名。服务器重启会丢失进行中的会话和战斗；参见 [Cloudflare 原生 WebSocket 示例](https://developers.cloudflare.com/durable-objects/examples/websocket-server/)。
- 离线存档由玩家持有和编辑；不同标签页或自建客户端仍可由同一人控制。因此“六个真实会话”不是“六个经过身份认证的人”。当前适用于朋友协作和友谊竞技，没有完整反作弊、账户身份或可信排行榜承诺。
- 接入的是部署者提供的服务器。客户端的类型、会话和奖励检查降低协议错误的影响，但不是对恶意服务器的独立权威验证。
